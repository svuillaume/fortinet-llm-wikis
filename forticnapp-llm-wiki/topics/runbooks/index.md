## Overview

Operational runbooks for FortiCNAPP cover five tightly linked areas: the REST API as the integration surface, the `lacework` CLI for day-to-day commands, custom policy authoring, cloud-provider onboarding, and targeted remediation patterns. This section synthesizes the recurring step-by-step procedures across the routed sources.

**API basics.** The Lacework FortiCNAPP API is a REST API that uses bearer-token authentication; API keys are created in the Console at Settings → Configuration → API Keys and require account-admin (or API-key write) permission [src: lacework-forticnapp-api-reference-105ae4.txt]. Keys are account-scoped (not org-wide), capped at 20 per user, do not expire, and must be disabled or deleted if rotated; after creation the secret should be downloaded and stored securely [src: lacework-forticnapp-api-reference-105ae4.txt]. New keys appear in the Console as an Access Key ID starting with `LWAK_` plus a secret that is shown only once [src: iamrollback-QUICKSTART.md]. To call the API, exchange the key for a short-lived token via `POST https://<account>.lacework.net/api/v2/access/tokens` with header `X-LW-UAKS: <secret>` and body `{"keyId": "<id>", "expiryTime": 3600}` — the default lifetime is 3600 s and the maximum is 86400 s [src: lacework-forticnapp-api-reference-105ae4.txt]. All further requests target `https://<account>.lacework.net/api/v2/...`; API v1 is no longer supported [src: lacework-forticnapp-api-reference-105ae4.txt]. For least privilege, prefer a read-only service user with endpoint-level permissions over handing out full-access keys [src: custom-policies-via-api.md].

**CLI and Terraform credentials.** The `lacework` CLI reads credentials from `$HOME/.lacework.toml`, written interactively by `lacework configure` [src: FortiCNAPP_API.md]. The file should be `chmod 600` and typically defines a `[default]` profile with `account`, `api_key`, and `api_secret`; the account name is the subdomain of the Console URL (for example, `https://prod-security-test.lacework.net` → `prod-security-test`) [src: iamrollback-QUICKSTART.md]. `lacework access-token` prints a short-lived bearer token that Terraform or raw `curl` calls can reuse [src: FortiCNAPP_API.md]. The CLI's `lacework api` subcommand issues arbitrary API verbs; for example, migrating a legacy policy suppression is done with `lacework api post '/Exceptions?policyId=lacework-global-68' -d '{ "description": "Except the dev account", "constraints": [ { "fieldKey": "accountIds", "fieldValues": ["716829324861"] } ] }'` [src: cli.txt]. The Terraform Lacework provider accepts the same credentials either inline (`account`, `api_key`, `api_secret`, or a short-lived `api_token`), via `LW_ACCOUNT`/`LW_API_KEY`/`LW_API_SECRET` environment variables, or by naming a `profile` from the TOML file [src: FortiCNAPP_API.md].

**Custom policies via API.** The end-to-end authoring flow is: obtain a token, discover datasources with `GET /api/v2/Datasources` and `/Datasources/{name}`, iterate on an LQL query with `POST /api/v2/Queries/execute` (which does not require saving the query), persist it with `POST /api/v2/Queries` under a unique `queryId`, then create the policy with `POST /api/v2/Policies` referencing that `queryId` [src: custom-policies-via-api.md]. Policies come in three types: **Violation** (one alert per violation; requires an `alertProfile`), **Compliance** (one alert per policy listing all non-compliant resources; carries framework `tags`, `references`, and `infoLink`), and **Manual** (recommendation-only, not supported for custom policies) [src: lacework-forticnapp-api-reference-105ae4.txt]. Required policy fields include `policyId`/`title`, `enabled`, `policyType`, `alertEnabled`, `alertProfile`, `evalFrequency` (`Hourly`/`Daily`), `queryId`, `severity`, `description`, and `remediation` [src: custom-policies-via-api.md]. Bulk status/severity changes are available (beta) via `PATCH /api/v2/Policies`, but only for LQL-based policies, not for Terraform-managed ones, and batches must share policy type, tag combinations, and (for Violation) source family [src: lacework-forticnapp-api-reference-105ae4.txt].

**Cloud onboarding (QUICKSTART-style).** The FortiCNAPP cloud-integration plugin walks users through AWS, Azure, GCP, and OCI onboarding without fabricating commands, invoked as `/forticnapp-integration [question]` [src: forticnapp-cloud-integration-QUICKSTART.md]. It covers CSPM configuration, CloudTrail/Activity-Log audit ingestion, agentless workload scanning, and DSPM, and lets users choose between Guided Configuration, Terraform, CloudFormation, CLI, or manual deployment [src: forticnapp-cloud-integration-QUICKSTART.md]. Typical scenarios include single-account vs organization-level AWS CSPM, Azure multi-subscription via a single app registration with management-group inheritance, GCP workload scanning (which has GCP role and VPC-quota prerequisites), and inquiring about OCI private-preview status and limitations [src: forticnapp-cloud-integration-QUICKSTART.md]. The plugin always warns that Terraform may modify resources, never exposes secrets, and never mixes guidance across providers [src: forticnapp-cloud-integration-QUICKSTART.md].

**iamrollback remediation pattern.** The IAM privilege-escalation runbook starts the same way (create an API key, place credentials in `~/.lacework.toml` with `chmod 600`, derive the account name from the Console URL) and then runs `./lacework-scan.sh` to surface roles that hold dangerous permissions such as `iam:SetDefaultPolicyVersion` (can roll back managed-policy versions) or `iam:UpdateAssumeRolePolicy` (can modify trust policies) [src: iamrollback-QUICKSTART.md]. Output rows include the role ARN, resource ID, and the offending `RESOURCE_CONFIG` statement so operators can identify the exact permission to revoke [src: iamrollback-QUICKSTART.md]. Remediation is explicit AWS CLI calls — `aws iam delete-role-policy --role-name <role> --policy-name <name>` to drop an inline policy, or `aws iam delete-policy-version --policy-arn <arn> --version-id v2` to remove a rollback-eligible old version — and scan scope can be overridden with `AWS_ACCOUNT_ID` and `AWS_REGIONS` env vars before re-running the script [src: iamrollback-QUICKSTART.md].
