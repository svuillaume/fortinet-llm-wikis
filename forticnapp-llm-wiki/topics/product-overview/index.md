## Overview

**What it is.** FortiCNAPP is Fortinet's SaaS Cloud Native Application Protection Platform, delivered read-only against the customer's AWS, Azure, GCP and OCI environments — it ingests configuration, control-plane logs, workload telemetry and identity data, and never writes back [src: forticnapp-adminguide-f51ed5]. The platform consolidates what the industry still ships as separate point tools: CSPM, CWPP, CIEM, DSPM, KSPM, CDR and code security in one console [src: SKILL].

**History — the Lacework rebrand.** FortiCNAPP is the former Lacework platform, acquired and re-badged by Fortinet; the administration guide, CLI binary and Terraform modules still carry the Lacework lineage (the CLI is `lacework`, config lives in `~/.lacework.toml`, and the datasource language is LQL) [src: forticnapp-adminguide-f51ed5][src: SKILL]. The data model, Polygraph engine and SaaS tenancy are inherited from Lacework; the Fortinet layer added FortiCloud identity, FortiCloud Organization units for multi-tenant access, and native Security Fabric connectors [src: forticnapp-adminguide-f51ed5].

**FortiCloud Organizations.** FortiCNAPP can be configured into a FortiCloud Organization hierarchy. FortiCloud Organizations is a centralized account-management service that consolidates multiple FortiCloud accounts into one Organization made of Organizational Units (OUs); accounts, assets and users are assigned to specific OUs with set permissions and scope, which gives the hierarchy and access model [src: pasted-forticloud-organizations-overview]. The Organization portal is opened from the **Support** dropdown in FortiCloud, and a user reaches an OU either by selecting it at login or from the dropdown in the banner [src: pasted-forticloud-organizations-overview]. In practice this is what lets one IAM user reach several FortiCNAPP tenants across a master account and its managed accounts [src: forticnapp-multicloud-org]; the step-by-step onboarding (create the Organization, invite and approve managed accounts, Organization-type permission profile) is in the ITF and IAM configuration guide [src: forticnapp-itf-process-and-forticloud-iam-configuration]. The source is the FortiCNAPP Administration Guide page "Navigating FortiCloud Services" (section FortiCloud Organizations), a short conceptual overview; it does not cover the invitation steps, per-OU permission profile details or how OU scope interacts with FortiCNAPP Access Profiles, so those remain sourced only from the two pages above.

**FortiCNAPP organizations (enrollment model, the former Lacework organization with accounts).** The administration guide states that FortiCNAPP organizations are part of FortiCloud Organizations [src: forticnapp-docs-organization-overview]. An organization is created by a **one-time enrollment** using an existing account: it aggregates security, compliance and access control across all of the company's accounts, up to **100 accounts**, and lets alerts, resource groups, team members and audit logs be managed per account inside it; a team member can hold access to several accounts and switch between them [src: forticnapp-docs-organization-overview]. **Enrollment is irreversible and covers every listed account.** The enrolling account's FortiCNAPP URL becomes the organization URL, and the organization and all its accounts assume that account's authentication method, which can break logins for some account admins and users until remediated [src: forticnapp-docs-organization-overview]. The console path is Account Settings › Organization View › Get Started Now, then promote an existing account admin, who keeps account-level rights and gains the organization admin role [src: forticnapp-docs-organization-overview]. Enrollment adds two roles, **organization admin** (view and edit organization settings) and **organization user** (view only). Authentication and usage settings move to the organization level, so an account admin with no organization role can no longer see those pages. The new organization starts with no organization-level alert routing or resource groups, and its dashboard shows aggregated events and compliance [src: forticnapp-docs-organization-overview]. The `forticnapp` skill gives the Terraform equivalents: `provider "lacework" { organization = true }` for organization-level resources and `subaccount = "<name>"` aliases per account; it also states a pre-enrollment checklist (all accounts belong, 100 or fewer, enrolling account chosen for URL and authentication, future org admin already an account admin) [src: skill-forticnapp]. **Open items:** the source says these organizations are part of FortiCloud Organizations but does not explain how enrollment accounts map to FortiCloud OUs and managed accounts, how organization roles relate to FortiCloud permission profiles and FortiCNAPP Access Profiles, or how the enrollment-account authentication rule applies now that FortiCloud login is replacing legacy login. Treat the FortiCloud OU model (above) and this enrollment model as related but not yet reconciled.

**The pillars.**

- **CSPM** — continuous configuration assessment against CIS, NIST, PCI, SOC 2 and custom benchmarks across all four clouds; drift is surfaced in the compliance dashboard and as alerts [src: SKILL][src: forticnapp-adminguide-f51ed5].
- **CWPP** — vulnerability, malware and secrets scanning on hosts and containers, available agentless (snapshot-based) and agent-based (eBPF Linux agent in user space, no kernel modules) for runtime detection [src: SKILL][src: forticnapp-adminguide-f51ed5].
- **CIEM** — identity and entitlement analysis across AWS, Azure and GCP identities, including overprivileged roles, unused credentials and risk scoring on the Identity Security surface [src: SKILL][src: forticnapp-adminguide-f51ed5].
- **DSPM** — discovery and classification of sensitive data in cloud storage; feeds Attack Path Analysis so a reachable path can be ranked by what it would actually expose [src: SKILL][src: forticnapp-adminguide-f51ed5].
- **Code Security** — IaC scanning, SCA and SAST wired into CI/CD so Terraform or container-image risk is caught at pull-request time rather than after deployment [src: SKILL][src: fortinet-genai-security-reference].
- **CDR** — ML anomaly detection on CloudTrail, Azure Activity Logs and GCP Audit Logs, surfacing composite alerts in the Threat Center rather than raw events [src: SKILL][src: forticnapp-adminguide-f51ed5].

**The Polygraph platform.** The engine underneath these pillars is Polygraph — a behavioral graph of cloud, host, container and Kubernetes activity that the console exposes as per-domain polygraphs (Cloud, Hosts, Containers, Kubernetes) [src: forticnapp-adminguide-f51ed5]. Polygraph is also what makes Attack Path Analysis work: individually modest findings (a public S3 bucket, an overprivileged role, a vulnerable VM) are stitched into an exploit chain and scored by the path, not the single finding [src: forticnapp-adminguide-f51ed5][src: SKILL].

**Security Fabric positioning.** FortiCNAPP ships with native Security Fabric integrations to FortiAnalyzer, FortiGate, FortiSIEM and FortiSOAR — alerts and context flow out to the SOC pipeline, and FortiGate can enforce AWS tag-based segmentation via EventBridge+Lambda based on FortiCNAPP findings [src: forticnapp-adminguide-f51ed5]. The field story runs on this fabric: Shift Left with CNAPP code-security and posture, Shield Right with FortiGate network controls and FortiWeb application-layer defense, with FortiAnalyzer as the correlation plane [src: subject][src: SKILL]. In the broader Fortinet AI architecture, FortiCNAPP is the cloud-posture leg of FortiAI-SecureAI alongside FortiAIGate, FortiWeb and FortiAppSec Cloud for securing the AI data center [src: fortinet-genai-security-reference].

**How it compares.** Against the three CNAPP incumbents the pattern is consistent. Wiz covers cloud workloads well but has no SaaS security and no network-layer integration [src: SKILL]. Prisma Cloud is comparable in breadth but is priced through complex credit metering and has limited SSPM depth [src: SKILL]. CrowdStrike Falcon leads on endpoint and treats cloud posture as a secondary pillar with no SSPM [src: SKILL]. Microsoft Defender for Cloud is strong on Azure/M365 but lacks parity on agentless AWS/GCP workload scanning and deep multi-cloud posture [src: SKILL]. FortiCNAPP's differentiators in field engagements are the unified cloud-risk workflow (network + data + identity + vulnerability + runtime context in one platform), AI-assisted alert investigation with composite alerts, and the Security Fabric tie-in that none of the pure-play CNAPPs can match [src: SKILL][src: fortinet-genai-security-reference]. For cloud-security practitioners the operating rule is the same across these pillars: prioritize by exposure, exploitability, privilege and blast radius — which is exactly how Attack Path Analysis ranks findings [src: SKILLS][src: forticnapp-adminguide-f51ed5].


### FortiCare → FortiCloud migration mapping (newly ingested)

FortiCNAPP customers fall into **single-account (single-tenant)** or **organization (multi-account)** shapes, and the migration to FortiCloud preserves that split: single-account → one FortiCloud account; FortiCNAPP organization → FortiCloud **Organization**; FortiCNAPP sub-account → FortiCloud **member account**. The behavioral change is **licensing**. In FortiCNAPP today, an organization carries **one license** and there is **no mechanism to assign vCPU usage to sub-accounts**. In FortiCloud, **each member account owns its own license**. The migration therefore **splits SKUs**: each FortiCNAPP sub-account is assigned its own SKU in FortiCloud, and because FortiCNAPP cannot subdivide license units upstream, each sub-account is seeded with **one license unit** at migration time. `(src: user-chat-forticare-forticnapp-org-mapping-2026-10-14)`

### Multi-tenant / sub-account support and legacy SAML (newly ingested)

FortiCNAPP **already supports multi-tenancy** (organization with sub-accounts), but **not yet for customers who authenticate through FortiCloud**. For new customers who need a multi-tenant environment, **legacy SAML authentication** can be enabled; it is **not an interim solution**. When FortiCloud authentication went GA, legacy SAML was intentionally placed **behind a feature flag**, because FortiCloud SAML is cumbersome to configure and **does not support JIT provisioning**. Enabling it puts the customer in a **legacy authentication state**, which still supports **converting a standalone account into an organization**. The note mentions "some caveats" without listing them, and gives no date for FortiCloud-native multi-tenancy. This partly answers the open item in the enrollment-model paragraph above on authentication now that FortiCloud login is replacing legacy login. Tags: FortiCNAPP Multi Tenant, Sub Account. `(src: user-chat-forticnapp-multitenant-legacy-saml-2026-10-15)`

### Polygraph v2 and Wiz's Security Graph: what each source says (newly ingested, 2026-10-23)

All Wiz statements are **Wiz claims** from its own pages, extracted through a summarizing fetch, not independent evidence.

- **Polygraph v2** (July 2026, GA) is a graph neural network over identities, actions, resources and source IPs. It compares an identity's current activity with its own history and feeds Composite Alerts [src: user-upload-forticnapp-news-releases-jul-oct-2026-2026-10-15; see topics/cwpp/index.md].
- **Wiz Security Graph** is described as a graph database and "digital twin" of the cloud environment that maps resource relationships and adds runtime and cloud-event context. Wiz uses it for root cause analysis, blast radius, attack paths and detection correlation [src: wiz-security-graph-incident-response-2026-10-23][src: wiz-defend-ga-2026-10-23].
- **Wiz detection** is described as built-in detections plus "behavioral analytics" that baselines users, service accounts, workloads and data resources and weighs unusual behavior against permissions, exposure and data sensitivity [src: wiz-defend-ga-2026-10-23][src: wiz-academy-ai-behavioral-analytics-2026-10-23]. Wiz calls this "system-focused rather than model-focused" [src: wiz-academy-ai-behavioral-analytics-2026-10-23].
- **Gap:** none of the three Wiz pages mentions graph neural networks or an ML architecture, and none says the Security Graph itself generates detections. This is an absence in the pages read, not proof that Wiz does not use such models. No independent comparison of detection quality or false-positive rates is in the wiki.

### Unified risk management, Explorer policies and Risk Insights (newly ingested)

The FortiCNAPP 26.3.0 admin guide (user-pasted, all features **preview**) describes unified risk management: the console separates **Threat** and **Risk** sections (consistent with the August 2026 Threat Center / Risk Center navigation change above). Risk Insights are produced by **Explorer policies**, which are built from saved Explorer (QBL) queries and generate risk insights, unlike LQL policies, which generate alerts (those surface in the Risk Alerts dashboard). `(src: user-paste-unified-risk-management-risk-insights-2026-10-22)`

- **Limit:** 25 enabled custom Insights per account (each sub-account independently), also enforced via API, CLI and Terraform; Fortinet-provided and disabled Insights do not count.
- **Cadence:** policies are evaluated every six hours; a fixed risk stays Active until the next evaluation marks it Resolved. The doc also says a new policy starts producing insights "within 24 hours" (not reconciled).
- **Categories:** Compliance, Data exposure, Identity and access, Vulnerability, else uncategorized. DSPM adds data in Risk Insights when enabled.
- **Remediation:** AI Assist text replaces static policy remediation only when confidence is above 0.6; otherwise the static text is shown. Jira alert channel enables ticket creation (Ticket Created does not track Jira status).
- Linked pages on creating/tuning/cloning insights and remediation tickets were not supplied. Complements the earlier video-based stub (vendor claims, "phase one"); no contradiction found.
