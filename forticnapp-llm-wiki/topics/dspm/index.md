# Dspm

Data Security Posture Management across AWS and Azure.

## Scope

This page indexes **38** source documents routed to this topic.

## Synthesized content

FortiCNAPP Data Security Posture Management (DSPM) discovers and classifies sensitive data in AWS and Azure object storage using an architecture that mirrors agentless workload scanning: a dedicated scanner runs in the customer's cloud, inventories datastores, applies pre-configured data policies, and reports findings back to FortiCNAPP [src: forticnapp-azure-dspm-integration.md]. Unlike CSPM onboarding, DSPM is not enabled from Settings > Integrations > Cloud accounts; it is deployed with Terraform and finished from Settings > DSPM in the console, where the operator chooses regions, scan frequency, max file size, and the specific containers to scan [src: forticnapp-azure-dspm-integration.md].

**AWS deployment.** DSPM for AWS is delivered through the `lacework/terraform-aws-dspm` module, which installs **global** resources once per integration and **regional** resources in each region where scanning should run, keeping scanner traffic in-region to reduce latency and avoid cross-region data movement [src: 11-dspm-aws.md]. The module builds the full scanner plane: a Lacework cloud-account integration, an ECS Fargate cluster and task definition for the scanner, an EventBridge rule for scheduled scans, an S3 results bucket, a Secrets Manager secret for Lacework credentials, a DynamoDB scanner cache, a dedicated VPC with subnets and an internet gateway, and the IAM roles and policies required for cross-account S3 access and ECS execution [src: 11-dspm-aws.md][src: aws-dspm.md]. Scoping is driven by three inputs: `regions` (required list), `scanning_account_id` (the account hosting the scanner), and `datastore_filters` (an object with `filter_mode` of INCLUDE, EXCLUDE, or ALL plus `datastore_names`) [src: aws-dspm.md]. Scan cadence is set with `scan_frequency_hours` (valid values 24, 72, 168, or 720) and `max_file_size_mb` (1–50) [src: aws-dspm.md]. The scanner container defaults to `lacework/dspm-scanner:latest`, task sizing to 1024 CPU units and 8192 MB, and resources are tagged `ManagedBy = terraform` [src: aws-dspm.md]. The AWS DSPM module should not be confused with the agentless *workload* scanner (`terraform-aws-agentless-scanning`), which deploys a similar ECS/VPC/S3/Secrets footprint but targets host and container vulnerabilities, uses the separate `lacework_integration_aws_agentless_scanning` resource, and runs the `public.ecr.aws/p5r4i7k7/sidekick` sidekick image rather than the DSPM scanner [src: terraform-aws-agentless-scanning-README.md].

**Azure deployment.** DSPM for Azure uses the `lacework/terraform-azure-dspm` module and the same global/regional split as AWS [src: 12-dspm-azure.md]. Instead of ECS, scans run as an Azure **Container App Job** against Blob storage; the module provisions a resource group, a Container App Environment with Log Analytics and Application Insights, a Key Vault holding the Lacework credential secret, an internal storage account and container for DSPM data with a blob-expiration policy, a user-assigned managed identity for the scanner job, an Entra application plus service principal for the data loader, and the RBAC role assignments — Key Vault access, a custom storage-account-reader role, scanner job operator, blob/table owner on internal storage, and Cost Management Reader — needed to read monitored storage and operate the scanner [src: 12-dspm-azure.md][src: azure-dspm.md]. Scoping is set with `integration_level` of `SUBSCRIPTION` (default) or `TENANT`, `scanning_subscription_id`, `tenant_id`, `regions`, and `datastore_filters` with the same INCLUDE/EXCLUDE/ALL semantics as AWS [src: azure-dspm.md]. `scan_frequency_hours` and `max_file_size_mb` follow the same validation ranges, and the recommended flow deploys in two stages — a `service_principal` submodule creates a dedicated deployment SP, then the main module consumes its object ID as `owner_id` [src: forticnapp-azure-dspm-integration.md]. Provider requirements pin `azurerm >= 3.80`, `lacework ~> 2.3` excluding 2.4.0, and `time >= 0.9` [src: azure-dspm.md].

**Operating model.** For both clouds the Terraform run only lays scanner plumbing; the operator then opens Settings > DSPM to pick regions, cadence, max file size, and the specific blob containers or S3 datastores to scan, after which the first scan starts within one hour of completing DSPM setup and recurs at the configured frequency [src: forticnapp-azure-dspm-integration.md].
