# Code Security

Shift-left: SCA, SAST, IaC, SBOM, VS Code extension, pipeline scanning.

## Scope

This page indexes **37** source documents routed to this topic.

## Synthesized content

FortiCNAPP Code Security is the shift-left side of the platform: it scans code, dependencies, infrastructure definitions, and container images before they ever reach a runtime workload, and it reconciles the findings with what the CNAPP sees in production. The product surface spans a Lacework CLI with pluggable scan components, a VS Code extension, an admission webhook for Kubernetes, and a Claude Code plugin, all driven by the same `.lacework/codesec.yaml` policy file.

**SCA (Software Composition Analysis)** inventories declared dependencies and matches them against the Lacework vulnerability feed. SCA is enabled under the `sca:` key of `codesec.yaml`, with sub-flags for `vulnEvaluation`, `licenseDetection`, `sast`, `scr` (secret), `linesOfCode`, `gitHistory`, and Application Context Filtering (`acf`, `acfLocations`) [src: RECREATE_PROMPT.md]. In the plugin, SCA uses the CLI's `--modified-files` flag to scope automatic scans to the files touched in the current session plus their companion manifests, which brings scan time on large repos from minutes to seconds; the full repo is still reachable on demand through `/fortinet:code-review` [src: README.md]. Open-source equivalents the field team pairs with FortiCNAPP for pre-assessment include `npm audit`, `pip-audit`, OWASP Dependency-Check, and Snyk [src: CODESEC_README.md].

**SAST** is handled by Lacework's built-in SAST plus Semgrep rule-packs (`p/security-audit`, `p/owasp-top-ten`, `p/cwe-top-25`) in the pre-assessment suite [src: CODESEC_README.md]. Semgrep catches the string-concatenated SQL and reflected XSS patterns typical of the demo targets [src: RECREATE_PROMPT.md].

**IaC scanning** is the most feature-rich surface. The `iac:` block in `codesec.yaml` enables scanning for Terraform, Terraform plans, CloudFormation, Dockerfiles, Helm, Kubernetes, Kustomize, OPAL custom policies, Checkov, and tfsec, with `pullRequest.statusCheck: any` and configurable `exitConditions` that fail the build on Critical or High [src: RECREATE_PROMPT.md]. Custom Rego policies live under `policies/opal/<name>/policy.rego` with a sibling `metadata.yaml` declaring `checkTool: opal`, `checkType: Terraform`, provider, and severity [src: RECREATE_PROMPT.md]. The pre-assessment suite layers Checkov, tflint, hadolint, and cfn-lint for parity in air-gapped reviews [src: CODESEC_README.md].

**SBOM** generation uses Syft (`syft . -o spdx`) or Trivy (`trivy image --format sbom`); container vulnerability scanning uses Trivy against built images before registry push [src: CODESEC_QUICK_REFERENCE.md][src: CODESEC_README.md].

**VS Code extension** — the demo repo pins `lacework-security.lacework-code-security` in `.vscode/extensions.json` as a workspace recommendation, so the extension prompt fires on first open and findings surface inline as the developer edits [src: RECREATE_PROMPT.md].

**OpenShift** — on OpenShift clusters, FortiCNAPP covers IaC misconfiguration detection on Terraform, Helm, and Kustomize in CI or pre-deployment; a DaemonSet agent delivers CWPP runtime visibility, behavior monitoring, and threat detection; registry and pipeline image scanning is supported; and an **admission webhook** blocks deployments on high/critical CVEs and policy violations using OPAL (OPA + Terraform rules). CIS/PCI/NIST compliance is "Limited — Custom rules can be defined in FortiCNAPP," and RBAC/identity monitoring is partial via the runtime agent [src: README_FortiCNAPP_OpenShift.md].

**CI/pipeline integration** — the Claude Code `code-security` plugin wires scanning in via two modes: **Pre-commit** (default) runs on the `PreToolUse` Bash matcher before `git commit` and rejects the commit on Critical/High in staged files; **Post-task** runs on the `Stop` hook, filters findings to the files changed in the session, and re-invokes Claude with fix options. Both modes run IaC and SCA scanners in parallel, dedupe repeat scans by file-content hash, and inject a `SessionStart` security-awareness context so Claude writes secure defaults from the first keystroke [src: README.md]. For non-Claude pipelines, the open-source suite ships drop-in GitHub Actions, GitLab CI, and Jenkins recipes that call a single `codesec_opensource.sh --all`, upload `security-reports/` as artifacts, and post PR comments with a truncated summary [src: CODESEC_QUICK_REFERENCE.md][src: IMPLEMENTATION_GUIDE.md]. Credentials for the CLI resolve from `~/.lacework.toml`, then `LW_ACCOUNT`/`LW_API_KEY`/`LW_API_SECRET`/`LW_SUBACCOUNT` env vars, then an interactive `lacework configure` prompt [src: README.md].
