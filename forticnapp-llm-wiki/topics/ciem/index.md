# Ciem

Cloud Identity & Entitlement Management: identities, permissions, attack chains.

## Scope

This page indexes **17** source documents routed to this topic.

## Synthesized content

FortiCNAPP's CIEM module answers "who can do what, where, and when did they last do it?" across AWS, Azure, and GCP, treating cloud identity — not network perimeter — as the primary breach vector [src: june-2026-cloud-identity-attack-chains]. It ingests the IAM configuration of each enrolled account daily (AWS IAM Access Advisor, Azure Entra ID + ARM RBAC, GCP IAM) and correlates granted entitlements with observed usage [src: june-2026-cloud-identity-attack-chains].

**Identity inventory.** On Azure the inventory depends on two separate reads: the Configuration integration's **Reader** role at Management Group or subscription scope resolves `Microsoft.Authorization/*` (RBAC role assignments, principals, scopes), and the **Directory Reader** Entra ID role plus admin-consented MS Graph permissions (`Directory.Read.All`, `User.Read.All`, `Group.Read.All`) resolves Entra users, groups, and app registrations [src: forticnapp-azure-ciem]. Without Directory Reader the view is partial — RBAC assignments appear, but Entra principals resolve as unresolved GUIDs and CIS/NIST identity controls show "Could Not Assess" [src: forticnapp-azure-ciem]. The pattern is visible in production tenants: a privileged RBAC dump of 12 User Access Administrator holders at tenant root, 28 Owner and 65 Contributor assignments at MG/subscription scope, and 53 assignments with unresolved principal IDs — likely deleted users or guests still carrying production access [src: azure-privileged-rbac].

**Entitlement analysis.** Each principal receives an identity risk score computed from `(Effective Permissions × Usage Gap × Blast Radius) / Compensating Controls` [src: june-2026-cloud-identity-attack-chains]. Effective permissions are resolved after policy inheritance, SCPs, and permission boundaries; usage gap is the share of granted actions never exercised in 90 days; blast radius weights the sensitivity of reachable resources (S3 with PII, Secrets Manager, RDS); compensating controls account for MFA, IP condition keys, and access boundaries [src: june-2026-cloud-identity-attack-chains]. For AWS, FortiCNAPP ships a right-sizing tool that converts observed CloudTrail activity into least-privilege policies: given one or more role ARNs or CSV exports, `generate-policy.py` emits JSON IAM policies containing only the actions actually used, honoring AWS's 10,240-char inline / 6,144-char managed limits via automatic splitting (`fewest-policies` / `by-service` / `none`) [src: ciem-remediations/README]. The tool explicitly carries forward log-heavy events (Lambda invocations, S3 reads) that CloudTrail does not record completely, controlled with `--(no-)include-unknown-actions`, and warns that observed activity is a starting point, not a complete entitlement spec [src: ciem-remediations/README].

**Attack chain detection.** CIEM is one of three layers in the Polygraph correlation engine, alongside CSPM posture and runtime behavioral baselines from the agent or agentless eBPF snapshot [src: june-2026-cloud-identity-attack-chains]. A single `GetSecretValue` call is noise; the same call at 03:14 UTC from a Lambda with no history of Secrets Manager access, correlating with an open CIEM finding of unused `secretsmanager:*` plus a CSPM finding of disabled S3 object logging on a DSPM-classified PII bucket, becomes a composite Critical alert [src: june-2026-cloud-identity-attack-chains]. Reported impact across 214 deployments: credential-abuse mean time to detect drops from 72+ hours (CSPM only) to 8 minutes, false positives from 340/week to 12, MITRE ATT&CK Cloud coverage from 34% to 79% [src: june-2026-cloud-identity-attack-chains]. Baselines take ~72 hours to establish, so a key stolen and used immediately will not anomaly-trigger on first use [src: june-2026-cloud-identity-attack-chains].

**Cloud provider coverage.** CIEM is native on AWS, Azure, and GCP; the AWS right-sizing tool is explicitly AWS-only [src: ciem-remediations/README]. **OCI is the exception: FortiCNAPP has CSPM and CWPP for OCI but no CIEM — no OCI IAM graph, no Identity Domains analysis, no compartment-level identity scoring, no cross-cloud identity unification covering OCI** [src: CORRECTION_FortiCNAPP_No_CIEM_OCI]. For OCI identity-first customers Wiz is the honest answer (full OCI IAM graph GA December 2025); FortiCNAPP wins OCI engagements on configuration compliance (CIS OCI 1.2.0), CWPP, and FortiGate network integration [src: CORRECTION_FortiCNAPP_No_CIEM_OCI]. SaaS identity (Okta, Entra for M365, Salesforce) is also out of CIEM scope and belongs to FortiCASB-SSPM [src: june-2026-cloud-identity-attack-chains].

**Operator setup (Azure).** Prerequisites: Entra Global Administrator (or App Admin + Privileged Role Admin), Owner on all target subscriptions, FortiCNAPP Administrator role [src: reference_forticnapp_azure_ciem]. Guided configuration generates a Cloud Shell script that creates the App Registration, assigns Reader / Security Reader / Key Vault Reader, and installs the FortiCNAPP CLI + Terraform; admin consent for MS Graph (`az ad app permission admin-consent --id <application-id>`) is the single step the wizard cannot automate and must be granted manually or the integration stays PENDING [src: forticnapp-azure-ciem]. No write-capable role (Contributor, Owner) is ever needed or wanted; validation lands 30–60 minutes after integration creation under Cloud Security → Resources and the Identity Security section [src: forticnapp-azure-ciem].
