# Onboarding AWS S3

FortiCASB pulls data from AWS S3 via RESTful API (guide text: the portal accesses collected data "with OAuth2.0 authentication"). It monitors and tracks S3 user activities and provides DLP Data Analysis for files stored on S3. Administrators and users can onboard cloud applications to a business unit; once added, all users in the business unit can view the app. Screenshots were not extracted from the guide; UI details below come from text only. [src: forticasb-admin-guide-24-4-b, p.58]

## Prerequisites

1. **Account requirement:** the AWS account user used must be an Administrator User (guide references AWS doc "setting-up-create-iam-user" for creating an administrative user).
2. **Activate Security Token Service (STS):** FortiCASB uses regional STS to reduce latency.
   1. In AWS console go to Identity and Access Management (IAM).
   2. Click **Account settings** in the left panel and expand **Security Token Service (STS)**.
   3. Activate **EU (Ireland)** if located in the European Union, otherwise activate **US West (Oregon)**.

[src: forticasb-admin-guide-24-4-b, p.58-59]

Overall order of work (Administrator User): AWS Policy Creation, AWS Role Creation, Update AWS Role External ID (optional), AWS Configure CloudTrail Setting, then Add AWS S3 Account in FortiCASB. [src: forticasb-admin-guide-24-4-b, p.59]

## 1. AWS policy creation

1. AWS console > IAM > **Policies**.
2. **Create policy**, open the **JSON** tab.
3. Replace the existing JSON with the following (line breaks inside some action names in the extracted text are wrapping artifacts):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Action": [
        "s3:Get*",
        "s3:List*",
        "s3:Put*",
        "s3:Delete*",
        "s3:CreateBucket",
        "iam:List*",
        "iam:Get*",
        "cloudtrail:LookupEvents",
        "cloudtrail:GetTrailStatus",
        "cloudtrail:DescribeTrails",
        "cloudtrail:ListTags",
        "cloudtrail:GetEventSelectors",
        "config:Get*",
        "config:Describe*",
        "config:Deliver*",
        "config:List*"
      ],
      "Resource": "*",
      "Effect": "Allow"
    }
  ]
}
```

4. Click **Review policy**.
5. Name the policy, e.g. `forticasb_authentication`.
6. Click **Create policy**. Keep the policy name for role creation.

The purpose of each AWS service in the custom policy is described in Appendix A - Amazon Policy Usage (guide p.558; not part of this page's source range). [src: forticasb-admin-guide-24-4-b, p.59-61]

## 2. AWS role creation

### Obtain External ID from FortiCASB
The External ID is described as a unique "32-bit" token generated by FortiCASB to meet AWS security requirements protecting the role.

1. Log into FortiCASB.
2. **Overview > Dashboard**, click **Add New**, select **AWS S3**, click **Add Selected Cloud App**.
3. Enter your **AWS Account ID** and click **Validate** to generate the External ID.
4. The External ID appears on the right; click copy.

If an AWS role for FortiCASB already exists and only the External ID must change, see "Update role External ID" below. [src: forticasb-admin-guide-24-4-b, p.61-62]

### Create the role
1. IAM > **Roles** > **Create role**.
2. **Select trusted entity**: **AWS account**.
3. Choose **Another AWS account** and enter Account ID `897379900121` (the AWS account FortiCASB uses to monitor the new role).
4. Select **Require external ID** and paste the External ID generated earlier. It must have been generated through FortiCASB using the same AWS account; otherwise the AWS account cannot be added.
5. Ensure **Require MFA** is NOT selected. Click **Next**.
6. Click **Filter**, select **Type**, then **Type: Customer managed**.
7. Select the policy created earlier. Click **Next**.
8. Enter a role name of your choice.
9. Click **Create role**.
10. Open the created role and copy the **AWS Role ARN**, e.g. `arn:aws:iam::123456123456:role/FortiCASBTester`. Keep it for FortiCASB.

[src: forticasb-admin-guide-24-4-b, p.62-64]

## 3. Update role External ID (optional)

If a role already exists, replace the old External ID with the newly generated one instead of creating a new role.

1. Log into AWS with the Administrator User.
2. Open IAM.
3. **Roles**; search and open the role used for FortiCASB.
4. **Trust Relationships** tab > **Edit trust relationship**.
5. Replace the value on the `sts:ExternalId` line with the FortiCASB-generated External ID.
6. Click **Update Trust Policy**.

[src: forticasb-admin-guide-24-4-b, p.65-66]

## 4. Configure CloudTrail

1. AWS console > **CloudTrail** > **Trails** > **Create trail**.
2. General details: enter a **Trail name**; keep default **Create a new S3 bucket**.
3. Uncheck **Log file SSE-LMS encryption** and **Log file validation**.
4. Scroll down, click **Next**.
5. Choose log events > Events > Event type: select **Management events** and **Data events**.
6. Manage events > API activity: keep **Read** and **Write** selected.
7. Data events: click **Switch to basic event selectors**.
8. Data event source: select **S3**, click **Next**.
9. Review; make sure the trail is configured as **multi-region trail**; click **Create Trail**.

[src: forticasb-admin-guide-24-4-b, p.66-68]

## 5. Add the AWS S3 account in FortiCASB

1. Return to the **Add AWS S3 Account** page; review the key configurations list; click **Next**.
2. Enter **AWS Role ARN**.
3. Click **Add AWS S3 Account**.

[src: forticasb-admin-guide-24-4-b, p.69-70]

## Update AWS S3 account

Complete the same AWS-side configuration first (policy creation, role creation, optional External ID update, CloudTrail setting). Then in FortiCASB:

1. **Overview > Dashboard**.
2. Open the AWS S3 account menu and select **Update Cloud Account**.
3. On **Update AWS S3 Account**, review the key configurations list; click **Next**.
4. Enter the **AWS Role ARN**.
5. Click **Update AWS S3 Account**.

[src: forticasb-admin-guide-24-4-b, p.71-72]

## Gotchas
- External ID must be generated in FortiCASB for the same AWS Account ID; self-made values will not work.
- Do not require MFA on the role.
- CloudTrail must be multi-region with Management and Data (S3) events, Read and Write; SSE-LMS encryption and log file validation unchecked.
- Policy grants `s3:Put*` and `s3:Delete*` in addition to Get/List (as printed in the guide).
- The guide says "AWS CloudTrail Configuration" when referring to where the Role ARN comes from; the ARN actually comes from the role step.
